Pathfinding Demystified: Implementing BFS, Dijkstra, and A* on a 2D Grid in Python

How does an autonomous game entity navigate a maze of obstacles to hunt down a target? We trace the evolutionary lineage of graph traversal from unweighted Breadth-First Search to heuristic-directed A* with complete Python implementations.

Core Algorithmic Insights

  • Graph Duality: A 2D grid is simply an implicit graph where each tile is a vertex connected to its 4 orthogonal neighbors (Up, Down, Left, Right).
  • BFS: Guarantees the shortest path in unweighted graphs using a FIFO queue, but searches blindly in all directions.
  • A* Formula: Evaluates nodes by $f(n) = g(n) + h(n)$, where $g(n)$ is actual cost from start and $h(n)$ is the estimated Manhattan distance to the goal.
  • Admissibility Rule: A heuristic must never overestimate the actual cost to reach the goal. Overestimating turns A* into an incomplete or sub-optimal greedy search.

1. Representing a 2D Game Board as a Graph

When game developers want bot enemies, NPCs, or automated snakes to navigate a world, they model the environment as a graph $G = (V, E)$. On a 2D grid:

  • Every grid coordinate $(x, y)$ is a vertex.
  • Transitions between adjacent coordinates (excluding walls and obstacles) are edges.

Because the graph is uniform, we do not need to store an explicit adjacency list in memory. Instead, we generate valid neighbors dynamically on-the-fly:

def get_neighbors(node, grid_w, grid_h, obstacles):
    x, y = node
    neighbors = []
    for dx, dy in [(0, -1), (0, 1), (-1, 0), (1, 0)]:
        nx, ny = x + dx, y + dy
        if 0 <= nx < grid_w and 0 <= ny < grid_h and (nx, ny) not in obstacles:
            neighbors.append((nx, ny))
    return neighbors

2. Breadth-First Search (BFS): The Baseline for Unweighted Grids

Breadth-First Search uses a First-In, First-Out (FIFO) queue (via collections.deque). It visits every tile at distance 1 from the start, then all tiles at distance 2, expanding like ripples in a pond.

While BFS guarantees the mathematically shortest path on unweighted grids, its fatal flaw is blindness: it expends just as much CPU power checking tiles behind the snake as it does checking tiles in the direction of the apple.

3. Dijkstra’s Algorithm: Introducing Movement Costs

When terrain features varying costs—such as mud that slows movement or mud that costs double stamina—BFS fails because the fewest number of tiles is not necessarily the cheapest path. Dijkstra’s algorithm replaces the simple FIFO queue with a Priority Queue (using Python's heapq module), always expanding the node with the lowest cumulative cost $g(n)$.

4. A* Search: Guiding Exploration with Admissible Heuristics

In 1968, researchers Peter Hart, Nils Nilsson, and Bertram Raphael discovered that Dijkstra’s algorithm could be dramatically accelerated by giving the priority queue an "estimate" of how close each tile is to the goal. This became the A* (A-Star) Algorithm.

The Golden A* Formula:
f(n) = g(n) + h(n)

• g(n): The exact cost traveled from the start node to node n.
• h(n): The estimated heuristic cost from node n to the goal.
• f(n): Total priority score (lowest score explored first).

For a 4-directional grid, the standard heuristic is the Manhattan Distance (taxicab metric):

manhattan_distance = abs(x1 - x2) + abs(y1 - y2)

6. Complete Python Implementation (A* with heapq)

Here is an optimized, production-grade implementation of A* pathfinding using Python's heapq:

import heapq

def astar_search(start, goal, grid_w, grid_h, obstacles):
    """
    Finds the shortest path on a 2D grid from start to goal.
    Returns: List of (x, y) coordinates from start to goal, or None if blocked.
    """
    def heuristic(a, b):
        return abs(a[0] - b[0]) + abs(a[1] - b[1])

    # Priority queue stores tuples of: (f_score, counter, current_node)
    counter = 0
    open_heap = []
    heapq.heappush(open_heap, (heuristic(start, goal), counter, start))

    came_from = {}
    g_score = {start: 0}

    while open_heap:
        _, _, current = heapq.heappop(open_heap)

        if current == goal:
            # Reconstruct path by following parent pointers backwards
            path = []
            while current in came_from:
                path.append(current)
                current = came_from[current]
            path.append(start)
            path.reverse()
            return path

        cx, cy = current
        for dx, dy in [(0, -1), (0, 1), (-1, 0), (1, 0)]:
            neighbor = (cx + dx, cy + dy)
            if 0 <= neighbor[0] < grid_w and 0 <= neighbor[1] < grid_h:
                if neighbor in obstacles:
                    continue

                tentative_g = g_score[current] + 1
                if tentative_g < g_score.get(neighbor, float('inf')):
                    came_from[neighbor] = current
                    g_score[neighbor] = tentative_g
                    f_score = tentative_g + heuristic(neighbor, goal)
                    counter += 1
                    heapq.heappush(open_heap, (f_score, counter, neighbor))

    return None  # No viable path exists

7. The Game AI Dilemma: Why Shortest Path ≠ Best Move

If you plug this exact A* algorithm into a Snake bot, the bot will play flawlessly until its body reaches approximately 20–30 tiles. Then, it will suddenly make a fatal mistake: it will turn into a tight pocket to grab an apple, eat it, grow, and discover the exit is blocked by its own tail.

This illustrates the fundamental difference between static pathfinding and game AI:

  • In static maps (like RPG dungeons or GPS navigation), the obstacles never move. A* is optimal.
  • In Snake, the obstacles are your own body, and every move clears the tile occupied by your tail tip while adding a tile at your head.

To build an immortal AI rival, modern implementations combine A* with a Reachability Flood Fill check: before taking the path to the food, the bot checks if a path will still exist between the food coordinate and the snake's tail tip. If no path exists, the bot refuses the food and chases its tail until space clears. Read our in-depth engineering breakdown: Engineering Real-Time A* AI Rivals.

8. Frequently Asked Questions

What is an 'admissible' heuristic?

A heuristic is admissible if it never estimates a cost greater than the actual lowest cost to reach the goal. Because a straight-line Manhattan distance is the absolute minimum distance on a 4-way grid with zero obstacles, it is guaranteed to be admissible.

Why did we include a tie-breaker counter in open_heap?

If two nodes have the exact same f_score, Python will attempt to compare the next element in the tuple. If the next element is the coordinate tuple, comparisons can fail or consume unnecessary cycles. A simple incrementing integer counter breaks ties cleanly in O(1) time.

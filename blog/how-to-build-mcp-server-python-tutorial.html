How to Build an MCP Server in Python: A Step-by-Step Tutorial

The Model Context Protocol turns AI assistants into agents that can call your code. Here is how to build your own MCP server in Python.

MS
Modern Snake Game
Published 2026-11-10

Why MCP Servers Matter

The Model Context Protocol (MCP) is an open standard that lets AI clients such as Claude, ChatGPT, and Gemini discover and call tools exposed by your application. Instead of pasting context into a chat, the model invokes a function and reads the result. For a freelance AI engineer or SaaS builder, an MCP server is the bridge between your business logic and every major AI assistant.

Prerequisites

  • Python 3.10 or newer
  • pip and a virtual environment
  • Basic familiarity with async Python

Step 1: Install the MCP SDK

Install the official SDK with the CLI extra so you can run and inspect servers locally.

pip install "mcp[cli]"

Step 2: Define Your First Tool

FastMCP uses decorators. A tool is any function with type hints and a docstring; the SDK turns it into a JSON schema automatically.

from mcp.server.fastmcp import FastMCP

mcp = FastMCP("weather")

@mcp.tool()
def get_weather(city: str) -> str:
    """Return the current weather for a city."""
    return f"Weather in {city}: sunny, 24C"

if __name__ == "__main__":
    mcp.run()

Step 3: Add Resources and Prompts

Resources expose read-only data (files, DB rows, API responses). Prompts are reusable templates the client can insert. Together with tools they form the three primitives of MCP.

@mcp.resource("config://app")
def app_config() -> str:
    return "version=1.2.0"

@mcp.prompt()
def review_code(code: str) -> str:
    return f"Review this code for bugs:\n{code}"

Step 4: Run Locally Over stdio

By default FastMCP speaks stdio, which is what Claude Desktop and most local clients expect. Run it directly.

python server.py

Point your client at the command and it will list the available tools automatically.

Step 5: Deploy Over HTTP

For remote clients, switch to streamable HTTP transport and containerize. A minimal Dockerfile works.

FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
CMD ["python", "server.py", "--transport", "streamable-http", "--port", "8000"]

Best Practices for Production

  • Validate inputs with Pydantic models, not raw dicts.
  • Return structured JSON, not prose, so models can reason over fields.
  • Add timeouts and retries around external calls.
  • Log tool calls with correlation IDs for debugging.
  • Version your tool schemas; never break existing clients silently.

Common Pitfalls

Blocking the event loop with synchronous I/O is the top mistake. Use async clients or run sync work in a thread pool. Also avoid leaking secrets in tool descriptions, which are visible to the model.

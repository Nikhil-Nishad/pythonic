1. The Fatal Flaw of Variable Timesteps in Browser Games

Most developers building their first HTML5 canvas game start with the classic variable timestep approach:

// The Naive Variable Delta Approach (Prone to Glitches)
let lastTime = performance.now();

function gameLoop(now) {
    const delta = (now - lastTime) / 1000; // in seconds
    lastTime = now;

    updatePhysics(delta);
    renderCanvas();

    requestAnimationFrame(gameLoop);
}
requestAnimationFrame(gameLoop);

While this naive approach looks clean on paper, in production browser environments it exposes severe fundamental flaws:

  • Tunneling & Bullet-Through-Paper Bugs: When a user switches tabs, experiences a CPU spike, or garbage collection pauses the main thread for 120ms, delta spikes. In a single frame, a game object moves 8 times its normal distance, teleporting straight through wall collision colliders.
  • High Refresh Rate Inconsistencies: On a 144Hz or 240Hz gaming display, requestAnimationFrame fires every 4.16ms to 6.94ms, whereas on standard laptops it fires at 16.67ms (60Hz), and on low-power mobile screens it can throttle down to 30Hz (33.33ms). Variable deltas introduce floating-point rounding divergence between platforms.
  • Non-Deterministic Replays & Anti-Cheat: In multiplayer or competitive leaderboard games, a gameplay run cannot be reliably verified or replayed on a server because minor differences in frame rate alter the exact trajectory and collision timings.

2. Glenn Fiedler's Accumulator Pattern: Fix Your Timestep!

The industry-standard solution popularized by Glenn Fiedler ("Fix Your Timestep!") decouples game state simulation from rendering. The physics simulation runs in discrete, constant time steps (e.g. exactly 16.666ms per tick), while rendering occurs as fast as the monitor refreshes.

Here is how the accumulator works conceptually:

  1. Measure the wall-clock time elapsed since the last render frame.
  2. Add this elapsed time into an accumulator buffer.
  3. While the accumulator has at least one full fixed timestep worth of time (e.g., 1000 / 60 = 16.666ms), consume that slice and execute one deterministic physics step.
  4. Calculate the remaining fractional time in the accumulator (alpha interpolation) and pass it to the renderer to smoothly interpolate between previous and current states.
The Core Golden Rule: Physics updates consume fixed time quanta. Rendering renders whenever the browser is ready, interpolating between the last two physics states to eliminate jitter.

3. Complete Production Implementation in JavaScript

Below is a production-hardened, zero-allocation game loop class incorporating spiral-of-death clamping and alpha interpolation:

export class DeterministicGameLoop {
    constructor(updateFn, renderFn, tickRate = 60) {
        this.updateFn = updateFn;   // Fixed deterministic logic (16.66ms)
        this.renderFn = renderFn;   // Variable visual rendering
        this.fixedDelta = 1000 / tickRate; // 16.6666ms
        this.maxAccumulatedTime = 250;     // Spiral of death prevention (max 250ms)

        this.accumulator = 0;
        this.lastTime = 0;
        this.rafId = null;
        this.isRunning = false;
        
        // Performance metrics
        this.fps = 0;
        this.frameCount = 0;
        this.lastFpsUpdate = 0;
    }

    start() {
        if (this.isRunning) return;
        this.isRunning = true;
        this.lastTime = performance.now();
        this.lastFpsUpdate = this.lastTime;
        this.accumulator = 0;
        this.rafId = requestAnimationFrame(this.step.bind(this));
    }

    stop() {
        this.isRunning = false;
        if (this.rafId) {
            cancelAnimationFrame(this.rafId);
            this.rafId = null;
        }
    }

    step(currentTime) {
        if (!this.isRunning) return;

        let frameTime = currentTime - this.lastTime;
        this.lastTime = currentTime;

        // Prevent "Spiral of Death" if tab was hidden or suspended
        if (frameTime > this.maxAccumulatedTime) {
            frameTime = this.maxAccumulatedTime;
        }

        this.accumulator += frameTime;

        // Consume fixed discrete slices for deterministic simulation
        while (this.accumulator >= this.fixedDelta) {
            this.updateFn(this.fixedDelta);
            this.accumulator -= this.fixedDelta;
        }

        // Alpha represents fraction of next tick elapsed (for smooth interpolation)
        const alpha = this.accumulator / this.fixedDelta;
        this.renderFn(alpha);

        // Track FPS
        this.frameCount++;
        if (currentTime - this.lastFpsUpdate >= 1000) {
            this.fps = this.frameCount;
            this.frameCount = 0;
            this.lastFpsUpdate = currentTime;
        }

        this.rafId = requestAnimationFrame(this.step.bind(this));
    }
}

4. Preventing the Dreaded Spiral of Death

What happens if your updatePhysics() takes 20ms to calculate, but your fixed timestep is 16.66ms?

On each frame, the accumulator grows faster than the loop can consume it. To catch up, the while loop runs multiple iterations, which takes even longer, falling further behind until the entire browser tab freezes completely. This phenomenon is known as the Spiral of Death.

We mitigate this with two strict safety guards:

  • Clamping Max Accumulated Time: As shown above with this.maxAccumulatedTime = 250, never allow the accumulator to store more than ~15 physics frames. If a freeze happens, drop the excess frames. Losing animation fidelity is infinitely better than hanging the user's browser.
  • Visibility API Pausing: When the user switches tabs, call loop.stop() on document.visibilitychange and reset lastTime on resume so no delta backlog builds up.

5. Hermite and Linear Interpolation for Silky-Smooth Visuals

Because rendering occurs at variable timestamps (say, 4.3ms into a 16.66ms tick on a 240Hz monitor), drawing only the latest discrete grid position produces visible micro-stuttering.

By computing alpha = accumulator / fixedDelta, the renderer interpolates smoothly between previousPosition and currentPosition:

// Smooth visual interpolation between physics ticks
function render(alpha) {
    ctx.clearRect(0, 0, canvas.width, canvas.height);

    for (const entity of entities) {
        // Linear interpolation: Lerp(prev, current, alpha)
        const renderX = entity.prevX + (entity.x - entity.prevX) * alpha;
        const renderY = entity.prevY + (entity.y - entity.prevY) * alpha;

        drawEntity(ctx, entity, renderX, renderY);
    }
}

With interpolation enabled, a 60-tick-per-second grid game like Modern Snake renders like butter at 120Hz, 144Hz, and 240Hz with zero visual micro-judder.

Frequently Asked Questions

Why is requestAnimationFrame better than setInterval(loop, 16)?

setInterval runs on an imprecise timer that is completely detached from the display's V-Sync cycle, causing persistent tearing and high CPU utilization. requestAnimationFrame synchronizes with the GPU refresh cycle and automatically pauses when the browser tab is hidden to save battery.

What is the recommended tick rate for 2D arcade games?

For grid-based or arcade titles, 60 ticks per second (16.666ms per step) provides the optimal balance of physics precision, collision accuracy, and CPU efficiency.

How does fixed timestep loop improve game security and leaderboard fairness?

Because physics calculations consume identical discrete time steps regardless of the player's hardware frame rate, the game becomes completely deterministic. The server can replay the exact sequence of player keypresses to mathematically verify high scores.

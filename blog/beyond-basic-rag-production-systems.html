Beyond Basic RAG: Building Production Retrieval-Augmented Generation Systems

Naive RAG gets a demo working. Production RAG needs hybrid search, reranking, evaluation, and cost control.

MS
Modern Snake Game
Published 2026-11-16

The RAG Gap

Retrieval-augmented generation sounds simple: embed documents, search by similarity, paste results into the prompt. That works for a prototype and fails in production because real queries are ambiguous, documents are messy, and users expect citations. Closing the gap requires treating retrieval as its own system with measurable quality.

Chunking That Preserves Meaning

Fixed-size chunks split sentences and lose context. Chunk by semantic boundaries (headings, paragraphs) with a small overlap, and store metadata such as source, section, and date alongside each chunk so filters can narrow results.

  • Target 300-800 tokens per chunk with 10-15% overlap.
  • Keep code blocks and tables intact.
  • Store the parent document id for citation.

Hybrid Search: Dense Plus Sparse

Pure vector search misses exact matches (names, IDs, error codes). Combine dense embeddings with BM25 keyword search and fuse results with reciprocal rank fusion. This single change often doubles recall on technical corpora.

from rank_bm25 import BM25Okapi
# dense results + bm25 results -> RRF fusion -> top-k

Reranking for Precision

Retrieve a wide candidate set (top 50) then rerank with a cross-encoder or a hosted reranker. Reranking is the cheapest way to lift precision without retraining embeddings.

Query Rewriting and Routing

Users ask vague questions. Rewrite queries into search-friendly form, expand abbreviations, and route to the right index (docs vs tickets vs code). A small classifier in front of retrieval prevents sending support questions to the engineering docs index.

Evaluation Harness

You cannot improve what you do not measure. Build a labeled dataset of question-answer pairs and track retrieval recall@k, answer faithfulness, and end-to-end task success. Run it on every change to chunking or models.

  • Retrieval recall: did the right chunk appear in top-k?
  • Faithfulness: is every claim supported by retrieved text?
  • Latency and cost per query.

Citations and Grounding

Force the model to cite chunk IDs and refuse to answer when retrieval is weak. Citations make answers auditable and reduce hallucination. Show users the source snippets so they can verify.

Cost and Latency Budgets

Cache embeddings and frequent queries, cap context size, and stream responses. Set a latency budget (for example 2 seconds to first token) and degrade gracefully with fewer chunks when the budget is exceeded.
